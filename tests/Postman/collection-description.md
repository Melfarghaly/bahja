# Bahga API v1 — بهجة

واجهة تطبيقات بهجة (تطبيق المعلمة، تطبيق وليّ الأمر، تطبيق الإدارة).

> هذه المجموعة **مولَّدة من استجابات حقيقية**: كل مثال نجاح وخطأ نُفِّذ فعلياً على الـ API قبل حفظه (`php artisan test --group=postman`).

## البدء خلال دقيقة
1. شغّل السيرفر محلياً: `php artisan migrate:fresh --seed && php artisan serve`.
2. استورد المجموعة وملف البيئة `Bahga-API-local.postman_environment.json`.
3. نفّذ طلبات **Login** الثلاثة (تُحفظ التوكنات في المتغيرات تلقائياً).
4. نفّذ **Me** لحفظ `tenant_id`، ثم أي طلب.

حسابات البيانات التجريبية (كلمة المرور `password`):

| الدور | الدخول |
|---|---|
| مالكة الحضانة | `owner@bahga.test` |
| معلمة | `teacher@bahga.test` |
| وليّة أمر | `01000000002` |

## الدخول
- **الموظفون:** `POST /v1/auth/tokens` (بريد أو هاتف + كلمة مرور).
- **أولياء الأمور:** بدون كلمة مرور — `POST /v1/auth/otp` ثم `POST /v1/auth/otp/verify` بالرمز المرسل بالـ SMS.

## الهيدرز
| الهيدر | القيمة | ملاحظة |
|---|---|---|
| `Authorization` | `Bearer <token>` | من `POST /v1/auth/tokens` |
| `X-Tenant-Id` | رقم الحضانة | من `GET /v1/me`؛ مطلوب لكل الطلبات ما عدا الدخول و`/me` |
| `Accept` | `application/json` | |
| `Accept-Language` | `ar` (افتراضي) أو `en` | لغة الرسائل؛ `code` لا يتغير |

## شكل الاستجابات
- **النجاح**: البيانات داخل `data`. القوائم المقسّمة تحوي `links` و`meta`.
- **المبالغ**: `{ "piasters": 185000, "formatted": "1,850 ج.م" }` — احسب بالقروش (عدد صحيح) واعرض `formatted`. لا تستخدم أرقاماً عشرية للمال.
- **التواريخ**: `YYYY-MM-DD`، والأوقات ISO-8601.
- **الأخطاء**: شكل واحد دائماً:

```json
{
  "message": "البيانات المرسلة غير صحيحة.",
  "code": "validation_failed",
  "errors": { "login": ["حقل اسم الدخول مطلوب."] }
}
```

`message` للعرض للمستخدم، و`code` ثابت لبناء منطق التطبيق عليه.

## أكواد الأخطاء
| HTTP | `code` | المعنى وما يفعله التطبيق |
|---|---|---|
| 401 | `unauthenticated` | التوكن ناقص/منتهٍ → شاشة الدخول |
| 402 | `plan_upgrade_required` | الميزة غير متاحة في خطة الحضانة → إخفاء الميزة أو رسالة ترقية |
| 402 | `plan_limit_reached` | تم بلوغ حد الخطة (`errors.resource`, `errors.limit`) |
| 403 | `forbidden` | الدور لا يسمح (أو مستلم غير مخوَّل في الانصراف) |
| 404 | `not_found` | غير موجود، أو ليس من حضانتك/أطفالك (لا نكشف الفرق) |
| 405 | `method_not_allowed` | طريقة HTTP خاطئة |
| 422 | `validation_failed` | أخطاء الحقول في `errors` |
| 429 | `too_many_requests` | انتظر `Retry-After` ثانية |
| 500 | `server_error` | خطأ غير متوقع (بلا تفاصيل داخلية) |

## حدود الطلبات
- عام: 120 طلباً/دقيقة لكل مستخدم.
- الدخول بكلمة المرور: 6 محاولات/دقيقة.
- طلب رمز SMS: 6/دقيقة لكل IP، و5 رموز/ساعة لكل رقم، و60 ثانية بين رمزين.
- التحقق من الرمز: 10/دقيقة، و5 محاولات خاطئة تُبطل الرمز.
- فتح عملية دفع: 10 طلبات/دقيقة.
- شاشة التحقق من المستلم (`pickup/verify`): 30/دقيقة لكل مستخدم.
